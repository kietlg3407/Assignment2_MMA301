# ShopMate — MMA301 Assignment 2

ShopMate is an Expo / React Native e-commerce demo. The core flow is:

`Remote catalog → search/paginate → product detail → cart → local persistence`

The app also demonstrates an anonymous Firebase-backed wishlist, a local notification when an item is added to the cart, and product recommendations generated by Gemini through a small Express backend.

## Requirements

- Node.js 18 or newer
- npm
- Android emulator (the Gemini backend URL below is configured for the standard Android Studio emulator)
- A Firebase project for the wishlist
- A Gemini API key for live recommendations

## Install

From the project root:

```powershell
npm install
Copy-Item .env.example .env
Copy-Item server/.env.example server/.env
npm install --prefix server
```

Edit the two local `.env` files using the setup steps below. These files are ignored by Git. Do not paste credentials into source files, commit them, or share them in chat.

## Configure Firebase wishlist

1. Create or select a project in the [Firebase console](https://console.firebase.google.com/).
2. Add a **Web app** to the project and copy its Firebase config fields into the matching `EXPO_PUBLIC_FIREBASE_*` variables in the root `.env`. These Firebase client config values are included in the app bundle; do not put service-account credentials there.
3. In **Authentication → Sign-in method**, enable **Anonymous** sign-in.
4. Create a **Cloud Firestore** database.
5. Publish the rules in [`firestore.rules`](./firestore.rules) from **Firestore → Rules**.
6. Restart Expo after changing `.env`, open Wishlist, add a favorite, then tap **Tải / đồng bộ từ Firebase**. Confirm the document appears at `users/{anonymousUid}/wishlist/{productId}`.

The rules permit an authenticated user to access only their own wishlist and validate the expected document fields. Do not replace them with open test-mode rules.

## Configure Gemini backend

1. Create a Gemini API key in [Google AI Studio](https://aistudio.google.com/apikey).
2. Set `GEMINI_API_KEY` in `server/.env`. Keep it only on the backend; never use an `EXPO_PUBLIC_` variable for this key.
3. Keep `GEMINI_MODEL` at the example default or set it to a model enabled for your API key. The current default is `gemini-3.8-flash`.
4. The root `.env.example` uses `http://10.0.2.2:3001`, which lets the Android emulator reach port 3001 on the development computer. For a physical phone, use the computer's LAN IP on the same Wi-Fi; for a deployed backend, use its HTTPS URL.
5. Start the backend in one terminal:

   ```powershell
   npm run dev --prefix server
   ```

6. Start the app from the project root in another terminal:

   ```powershell
   npx expo start
   ```

7. Check backend readiness at `http://localhost:3001/health` on the development computer. `geminiConfigured` must be `true`. In the Android app, open **AI**, enter a shopping need, and request recommendations.

The backend sends the API key in the `x-goog-api-key` request header and limits submitted needs/catalog size. The app and backend both validate recommended product IDs against the submitted catalog. If the backend key/model is invalid or the service is unavailable, the AI screen displays an error; local catalog and cart features remain available.

For a public deployment, configure the secret in the host's secret manager, use HTTPS, and add appropriate CORS restrictions, rate limiting, and abuse protection. Do not deploy the local `.env` file.

## Architecture and limitations

- Product catalog: DummyJSON through `src/services/products.js`.
- Shared cart and local wishlist: React Context in `src/context/ShopContext.js`, persisted with AsyncStorage.
- Cloud wishlist: Firebase Anonymous Auth + Cloud Firestore in `src/services/firebase.js` and `src/services/wishlist.js`.
- AI: Expo client → `server/server.js` → Gemini API. The API key remains on the backend.
- Notification: the app requests permission in Settings, offers a test notification, and sends a local business notification when a product is added to the cart. This is not remote push messaging.
- If the current Expo Go runtime reports notifications as unavailable, use a development build (the app config includes the `expo-notifications` plugin):

  ```powershell
  npx eas-cli@latest login
  npx eas-cli@latest build:configure
  npx eas-cli@latest build --platform android --profile development
  ```

  The `development` EAS profile in [`eas.json`](./eas.json) creates an installable APK. After the cloud build finishes, download and install the APK on the Android emulator/device. Then run `npx expo start --dev-client --lan` from the project root and open the project using the installed development build, not Expo Go. If using LDPlayer, make sure it can reach the computer's LAN IP and allow Node.js through Windows Firewall on the private network.
- Checkout is a demo only; no payment is processed.
- Anonymous Firebase identity is not an account recovery mechanism. Linking accounts is not implemented.
